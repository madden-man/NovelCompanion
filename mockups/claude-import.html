    Proposal queue

    AI-3 no write tool, proposals only · ED-7 nothing saved without approval

    Claude has no tool that writes to the bible. Everything it wants to change arrives here as an exact before and after. The live value beside each card is what the bible holds right now. It changes only when you approve.

    Excel import mapping

    IM-1 mapping with preview, saved per file · IM-2 failed rows reported · IM-3 re-import updates, never duplicates · IM-6 source recorded · IM-7 newest source wins, conflict becomes an open question · A12 table and grid shapes

    Importing East Winds_ World.xlsx (modified 2026-08-23). Pick a sheet, choose its shape, map columns to fields, and check the preview before anything is written.

    Re-import the same file

    The file was edited and imported again. Each change is listed; nothing is applied until you approve it. Matching rows update existing entries by their recorded source location, so no duplicates appear.

    Conflict between sources

    Two sources give Dawn a different birth year. The importer keeps the value from the most recently modified source and files the disagreement as an open question so you can edit through it.

    Word and Google Docs import

    IM-4 backstory, chapter, or note with headings kept · IM-5 optional structured proposals · MS-1 italics and scene breaks kept · AI-5 imported text is never an instruction

    Bring a document in as what it is. Headings, italics and scene breaks survive. Claude can read it and propose entries, which land in the queue above for your approval.

    Preview

    The highlighted line is part of the document. The app passes it to Claude as text to analyse, never as an instruction, and Claude cannot delete anything in any case (AI-3).

    Google Drive

    GD-1 read-only desktop sign-in · GD-2 linked files · GD-3 changes reported, never applied silently · GD-4 export as Markdown and JSON · GD-5 disconnect removes tokens

    Drive is an import source and a backup target, never a two-way sync. The app works fully without it.

    Snapshots, bibles and settings

    BK-1 daily and before imports · BK-2 restore takes a snapshot first · BK-4 no partial writes · ARCH-8 many bibles · ST-1 settings

    Snapshots are complete local copies of the database. Restoring one first takes a fresh snapshot, so a restore can itself be undone.
