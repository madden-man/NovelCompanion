# A47 guard brief: instructions, housekeeping, minting and the manuscript lock, stored side (IP-15 to IP-18)

Read `docs/briefs/A47-common.md` first. You own the Claude runtime and conversations, the repository's purge, empty, prune and manuscript guard, the session re-import by chapter, the proposal shapes for list items, and the tests the common brief lists. Branch `a47-guard`, worktree `.claude/worktrees/a47-guard`. The screens come in wave 1 (`a47-house`, `a47-desk`, `a47-continuity`); you build the stored side and the channels, with the fewest renderer lines that keep the app compiling and green.

Where things are today: `src/main/claude/runtime.ts` (`FeatureDefinition.instructions`, `systemPrompt()` prepends the shared rules and the AI-4 sentence), `features/briefs.ts` 66, `summaries.ts` 22, `alignment.ts` 27, `prompts.ts`, `src/shared/claude.ts` 294 to 308 (conversations), `src/main/db/repository.ts` (the one write path; the trash at `entry.delete` and `entry.restore`; revisions appended on every write), `views.tsx` 315 to 402 (the Trash view, no purge), `history.tsx` 47 to 206, `src/main/claude/features/capture.ts` 46 to 50 (Claude cannot add list items), `src/shared/schema/proposal.ts`, `review.tsx` 141 to 182, `src/shared/schema/story.ts` 91 and `manifest.ts` 181 (`manuscriptText` as an ordinary long text), `src/main/session/*` (MS-1 import, the re-import diff in `sessions/manuscript.tsx`).

Deliverables:

1. **IP-15 instructions.** A `meta` document `claudeInstructions` holding the writer's text per feature (`briefs`, `alignment`, `summaries`, `importProposals`, `capture`, `panel`; absent means the default). Channels `claude.instructions.get` (every feature: the default, the stored text or null, and the fixed footer text) and `claude.instructions.set` (feature, text or null to reset). `systemPrompt()` composes: the writer's text when set, else the feature's default; then the fixed footer, which is the shared rules plus the AI-4 sentence, unchanged. The unit test that asserts the sentence in every prompt (find it under `tests/unit/claude*.test.ts`) must still pass, and a new one proves that a stored instruction appears in the prompt above the footer and cannot remove the sentence. An undo command for a set in `src/shared/undoCommands.ts`.
2. **IP-16 housekeeping.** Repository methods and channels: `entry.purge` (collection, id: removes the document and its revisions in one transaction, refuses an entry that is not in the trash, returns the counts), `trash.empty` (every trashed entry across collections, in one transaction, returns the counts), `revisions.prune` (collection, id or whole bible, `before` an ISO date, `dryRun` returns the count without deleting), `claude.conversation.rename`, `claude.conversation.clear` (messages go, the title stays), `claude.conversation.delete`. None of these are undo steps (the A40 rule); make sure the read model and the search index drop purged entries and that a purged entry's backlinks on other entries are left as dangling links the warnings already report (check `src/shared/domain/warnings.ts`). Integration tests for each, including the refusals and that a purge is not in `revisions`.
3. **IP-17 minting.** `propose_change` and the proposal schema accept a list-item proposal: `{ kind: 'listAdd', listId, label, parentId? }` alongside creates and updates; a proposal set may hold one and the entries that use it (a community line whose `communityId` names the new item by a temporary ref that approval resolves). `proposal.diff` renders it as a field ("Community: + Jinan"), `proposal.approve` creates the item first then the entries, `proposal.reject` drops it. The capture feature's tool description tells Claude it may add a community, event category, region, language or tag when none fits. Tests on the recorded fake: a recording that proposes "Add culture for Jinan, 2045" as a community plus a line (add the recording to `fixtures/claude/recordings.json` the way the others were made; do not call the real API).
4. **IP-18 the manuscript lock.** `chapters.manuscriptText` (and `manuscriptSource`, `sourceFile`) are system fields in the manifest (`f.system`, so the generic editor shows them read-only), the repository refuses an `entry.update` patch that touches them unless the call carries an internal importer flag (a second argument on the repository method, never on the IPC channel), with the error "The manuscript text is imported, not edited here. Use Re-import." A proposal whose patch touches them is rejected when it is made, with that reason in the proposal's record. A channel `manuscript.reimport` (chapterId) re-reads the chapter from its `manuscriptSource` through the existing MS-1 path and returns the same diff shape the Manuscript tab shows, so the Re-import buttons on the chapter page and Relevant to Session (wave 1) are one call. Tests: the refusal through the write path, the importer still writing, the proposal rejection, and re-import on the fixture's Word chapter.
5. **Renderer, fewest lines.** Whatever stops compiling or a test that stops passing because a field became system or a proposal kind was added: change the fewest lines and list them. The screens themselves are wave 1.

Report every channel with request and response shapes, the repository method names, the recording you added, and the exact error strings, so `a47-house`, `a47-desk` and `a47-continuity` can code against them.
