# M10 brief: settings, performance, packaging, final audit

Criteria: ST-1, NF-1 to NF-4, ARCH-6, every earlier criterion re-checked. Read first: `docs/ARCHITECTURE.md`, `SPEC.md` sections 5.19, 6, 8 (T-4 and T-6 in full), amendments A2, A15, A17, A23, and `PROGRESS.md`. Then the whole codebase.

Deliverables, keeping `npm test` green:

1. **Settings** (ST-1): one settings screen covering the API key (masked, replace only), per-feature models, brief window and size budget, romanization systems per language, snapshot count, MongoDB connection (masked, replace only, with a test-connection button), Drive connection, light or dark or system appearance (applied live through `data-theme`). Settings live in the bible-independent `settings` document in `novel_companion` plus the keychain for secrets; the JSON export includes settings (BK-3).

2. **Offline behaviour** (ARCH-6): when MongoDB is unreachable at launch or mid-session, a plain message with what to do, an offer to open the most recent local snapshot read-only (a read-only read model loaded from the snapshot files, every write control disabled with a visible reason), and no write ever reported as saved when it was not. Test with the connection dropped mid-session in integration (close the client) and at launch in e2e (point the test URI at a closed port).

3. **Performance** (NF-1, T-6): a generator for 5,000 entries and 100 chapters (characters, events, chapters with text, beats, facts) loaded into a local MongoDB; tests assert launch to first paint under 3 seconds (measure in e2e from app launch to the dashboard rendered, including the read model load), search under 200 ms, every timeline query under 100 ms, tree redraw under 500 ms with the 200-person tree. Fix whatever fails rather than relaxing the numbers.

4. **Accessibility and errors** (NF-2, NF-3): every action reachable by keyboard: add an e2e test that tabs through each screen and activates its primary controls without a mouse; contrast checks of the token pairs in both themes with an automated WCAG AA check over the CSS tokens; a sweep of every user-facing error string: plain language, what to do next, no raw codes (a unit test greps the renderer for `Error:` with a code and for raw exception messages reaching the UI).

5. **Packaging** (NF-4): `npm run package` produces an unsigned arm64 and x64 macOS dmg with electron-builder, the Agent SDK binary unpacked from asar, the app launches from the dmg with the keychain entries present, and the packaged app passes a smoke e2e (launch, open the East Winds bible, dashboard renders) using `NOVEL_COMPANION_ALLOW_TEST_URI=1` only for the test run.

6. **Final audit**: re-run every test, then walk `SPEC.md` criterion by criterion and update `PROGRESS.md` with status and evidence for every one, listing any criterion not met with the reason. Do not change the spec.

7. **Journey test** (`tests/journey/`): a Playwright run against the packaged app, with a fresh bible and the fixture imported through the interface, that plays a writer's session end to end: launch, dashboard shows the last note; set story time to 2045; open the tree and check ages; import the fixture workbook with a saved mapping; create a chapter with two strands; Start session on it and get a brief (fake Claude injected through the not-packaged flag or a recorded-response mode switch in settings for the packaged run); mark a chapter written, approve its summary, promote one entry to canon; run Check alignment, resolve one finding with Manuscript wins and undo it, one with Rewrite recommended; ask the question panel who is alive in 2075 and see the read list; take a snapshot, edit a character, restore the snapshot; export JSON and Markdown; close the app and answer the stop prompt; relaunch and see the note. Each step asserts visible state. `npm run test:journey` runs it and is listed in the README.

Constraints: no em dashes; no spec changes; test names start with the criterion ID. Report: `npm test` and `npm run test:journey` tails, the updated `PROGRESS.md` summary (count of pass and fail), files changed, anything not done with the reason.
