# Fast suite brief

Goal, in Tommy's words (2026-10-12): make `npm test` faster. Today a quiet full run is about 14 minutes, nearly all of it in the e2e suite, and most of that is fixed cost: every spec file starts its own `MongoMemoryReplSet` and its own Electron app, the files run one at a time, and `electron-vite build` runs before every e2e run. Target: a quiet full run under 6 minutes with every test still proving what it proves now.

Read first: `docs/ARCHITECTURE.md` (rules, "Local development", "Fixture novel"), `playwright.config.ts`, `tests/e2e/helpers.ts` (`launch`), any three spec files' `beforeAll`, `tests/helpers/mongoGlobalSetup.ts` (the vitest global setup, with its WiredTiger `file_manager` flags that stopped ENFILE), `src/main/secrets.ts` (the test seams `NOVEL_COMPANION_TEST_MONGODB_URI`, honoured only for a localhost URI in an unpackaged build), `src/main/db/connection.ts` and `bibles.ts` (ARCH-8: the app uses the one database `novel_companion`; `tests/unit/single-database.test.ts` asserts no `listDatabases` and no other `.db(` call), `package.json` scripts.

Deliverables:

1. **One replica set for the whole e2e run.** A Playwright global setup starts one `MongoMemoryReplSet` (one node, wiredTiger, the same `file_manager` flags as the vitest setup) and writes its URI for the workers; global teardown stops it. Each spec file gets its own database on that server so files stay isolated: add a test seam `NOVEL_COMPANION_TEST_DB_NAME`, honoured under exactly the same conditions as the test URI seam (localhost URI, unpackaged build, or the packaged allow flag), that replaces the database name `novel_companion` for that process. Keep ARCH-8 intact: one `.db(name)` call site, `single-database.test.ts` still passes (update its assertion only if it counts the literal), and a unit test proves the seam is ignored for a non-local URI and in a packaged build without the allow flag. `launch()` in `helpers.ts` takes the shared URI and a per-file database name (derive it from the spec file name) so spec files lose their `MongoMemoryReplSet.create` and `server.stop()` lines. Tests that assert ARCH-8 behaviour against a database name must keep asserting the real name in production code paths.
2. **Workers.** Turn on parallel spec files in `playwright.config.ts` (`workers: 3` on a machine with 8 or more cores, else 2; `fullyParallel` stays off because files are serial inside). Check every spec for shared global state that breaks under parallel files: the keychain (tests use the memory store, confirm), `NOVEL_COMPANION_USER_DATA` (each launch must get its own temp dir), fixed ports (the fake Google server in `tests/helpers/fakeGoogle.ts`, anything else: use port 0 and pass the port), fixed file paths in the scratch space, `localStorage` (per Electron user data dir, so fine if dirs differ). Fix what you find.
3. **Skip the build when nothing changed.** `test:e2e` builds only when `out/` is older than the newest file under `src/` (a small node script `scripts/build-if-stale.ts`), and `test:e2e:force` always builds. The same for `test:journey` through `scripts/ensure-package.ts` if it has the same problem.
4. **Measure.** Record in your report the full `npm test` wall clock before (from a clean quiet run; `git stash` is forbidden on this machine, so measure on `main` in the main checkout only if nothing else is running, otherwise take the 14 minutes as the baseline) and after, with the per-suite split. Run the full suite at least twice after the change to catch order and parallel flakiness; a test that fails only under parallel files is a bug in the test to fix, not a reason to drop a worker.
5. **Docs.** Update `docs/ARCHITECTURE.md` "Local development" and the README commands section: how the e2e run is laid out now, the new seam, how to run one file (`npx playwright test tests/e2e/x.spec.ts` must still work on its own, so the global setup must run for a single-file run too).

Rules: ARCHITECTURE.md binds (pure logic in `src/shared/domain`, one write path, the renderer has no network). No em dashes. Test titles keep their criterion IDs. Do not change what any test asserts except for the mechanics above. Work only in this worktree, commit on branch `fast-suite` as you go, do not merge or push. Before each full run check `sysctl -n vm.loadavg`; if the one-minute load is above 25 someone else is using the machine, wait and try again. Report: commands with last lines, before and after timings, every test you changed and why, anything not done.
