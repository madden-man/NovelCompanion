# M7 brief: manuscript, session brief, dashboard

Criteria: MS-1 to MS-5, SB-1 to SB-9, DB-1 to DB-4. Read first: `docs/ARCHITECTURE.md`, `SPEC.md` sections 5.10, 5.11, 5.21, 8 (T-2 brief end to end), amendments A4, A5, A11, A17, A18, A19, A21, and the mockups `mockups/brief-continuity.html` (inputs, the ten selection steps, manifest hash, brief layout, budget, Claude unavailable, save and export, mark as written) and `mockups/app-shell.html` (dashboard, Start session flow). Then the code from M0 to M6.

Deliverables, keeping `npm test` green:

1. **Manuscript** (MS-1 to MS-5): chapters hold manuscript text imported from `.docx` (M5 parser) or Google Docs (M9; design the import entry point so a Drive source plugs in) linked to the source file; italics and scene breaks kept; marking a chapter as written offers a Claude-generated summary in an editable box with Approve and Discard, saved only on approval (MS-2); then offers the planned entries this chapter establishes (entries linked to the chapter or its strands with status planned) as a list with per-item approval to promote to canon (MS-3); re-importing a changed chapter shows a text diff and marks the summary as possibly out of date (MS-4); no code path writes to any manuscript file or Doc, and a static test asserts the manuscript field is written only by the import path (MS-5).

2. **Deterministic selection** `src/shared/domain/brief/select.ts` (SB-1 to SB-3, SB-6, SB-9): inputs are a chapter (and strand, default primary) or a story year plus POV with optional place and present characters; implement the ten steps of SB-2 exactly as written with the A18 definitions, per strand when a chapter has more than one; custom sections per their CS-3 rule; output a manifest of entry IDs grouped by step with the drop priority order and the character budget (setting, default 40,000) applied, recording what was dropped; the manifest is sorted and hashed, and a test asserts the same inputs and data give an identical manifest across runs and across a fresh process; add and remove entries from the selection and regenerate (SB-9). Unit tests against the fixture with hand-written expected manifests for two chapters (one with two strands) stored in `fixtures/expected/briefs/` (hand-written, never generated; you may write these expected files because section 7 says they are hand-written from the rules, but write them by reading the spec rules, not by running the code, and say so in the file header).

3. **Brief generation** (SB-4, SB-5, SB-7, SB-8): the Claude feature `brief` takes the manifest's contents and returns a structured brief with these sections in this order: characters and their ages, ongoing world events, cultural expectations in this moment, what has happened to them so far, who knows what, loose threads, open questions, planned ahead (A17 and SB-5); every item cites entry IDs; code verifies every cited ID is in the manifest and flags any that is not, visibly (SB-4); canon and planned material are separated in the structure and the rendering, and nothing after the story year appears outside "planned ahead" (SB-5); when Claude is unavailable the structured brief renders from the manifest with no synthesis (SB-7); briefs are saved in a `briefs` collection linked to the chapter, editable like any entry, exportable as Markdown and PDF through a save dialog (SB-8); the model is the briefs setting, default `claude-opus-5-5` (DB-4).

4. **Dashboard** (DB-1 to DB-3): the app opens on it: last session-log note, current story time, current position (last chapter marked written in reading order), open questions count, open rewrite tasks (M8 fills the list; show the count from the `rewriteTasks` collection), and two primary controls, Start session and Check alignment (Check alignment is wired in M8; show it disabled with a note until then). Start session: pick a part, chapter, strand, or year plus POV; show the selection summary; Generate; the brief streams; on completion a session-log entry is created linked to the section and the brief, and the story time is set to the section's year (DB-3). SL-1's close-prompt from M4 stays.

5. **Tests**: unit (selection with expected manifests, hash stability, budget drops in the fixed order, citation verification with a planted bad ID, canon and planned separation, planned-ahead placement); integration (brief end to end with the fake Claude and recorded output, saved brief linked to the chapter, regenerate after removing an entry changes the hash, mark as written with summary approval and canon promotion, re-import diff); e2e (Start session from the dashboard on a fixture chapter, see the brief, see the session log entry and story time change; mark a chapter written; export Markdown).

Constraints: no em dashes; pure logic in `src/shared/domain/`; test names start with the criterion ID; the fake Claude must be used in the main suite. Report: `npm test` tail, criterion to test names table, files changed, anything not done with the reason.
