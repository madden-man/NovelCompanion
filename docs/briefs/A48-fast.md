# A48 fast brief: branch `a48-fast` (CR-7, CR-8, main's side of CR-9, the AI-4 and Route C tests of CR-10)

Read `docs/briefs/A48-common.md` first. You build Route B as a sixth Claude feature and trim Route C, on the main side. The router (`routeCapture`) is a placeholder on `main` that returns one Route C fact with nothing resolved; build against `types.ts`, test with hand-built `CaptureRouting` values, and never wait on the router branch.

## What exists

- `src/main/claude/features/capture.ts`: today's capture (KB-6), its instructions, the list lines, `storyTimeWords`, `prepareCaptureDraft`, `captureTools`. `runtime.ts` `runFeature` runs any `FeatureDefinition`; `finish` parses the output schema and may queue `def.proposals(...)` drafts through `queueDraft`. `proposals.ts` holds `ProposalDraft` and `queueDraft`.
- `src/shared/claude.ts`: `CLAUDE_FEATURES`, `DEFAULT_MODELS`, `FEATURE_INFO`, `claudeContract` (the `claude.capture` request now takes optional `hints: CaptureHint[]`).
- `src/main/claude/tools.ts`: `bibleTools(session, sink)`, `get_entry` returns the whole document (capped at 40,000 characters).
- `handlers.ts` `'claude.capture'` builds the input and calls `runtime.runFeature(session(), FEATURES.capture, ...)`.
- Tests: `tests/unit/capture.test.ts`, `claude.test.ts` (the AI-4 prompt test walks `FEATURE_LIST`; the free-text channel test lists the channels that carry text), `claude-guard.test.ts` (IP-15 instruction views per feature); `tests/integration/capture.test.ts` runs recorded captures through the fake. `fixtures/claude/recordings.json` is an array of `{ name, feature, match, steps }` where `match` is a substring of the prompt and `steps` are tool calls, text and the final `result`.
