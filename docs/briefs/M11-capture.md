Read `docs/briefs/M11-common.md` first. You own new `src/renderer/src/workspace/capture.tsx` and `capture.css`, new `src/main/claude/features/capture.ts` (registered in `features/index.ts`), `src/shared/claude.ts` (add feature `capture` to `CLAUDE_FEATURES`, `DEFAULT_MODELS` (`claude-sonnet-5-5`), `FEATURE_INFO`), the IPC channels you add in `src/shared/ipcSession.ts` or a new `src/shared/ipcCapture.ts` (register it where the others are), `fixtures/claude/recordings.json` (append recordings only), new `tests/e2e/capture.spec.ts`, unit and integration tests for the feature, and one wiring line each for `<CaptureBox />` next to `<StopPrompt />` and an Add button next to `AskClaudeButton` in the status bar of `Workspace.tsx`. Read how the panel feature works end to end before starting: `src/main/claude/features/panel.ts`, `runtime.ts`, `tools.ts` (`propose_change`, `queueDraft`), `proposals.ts`, `src/renderer/src/workspace/claude.tsx` (streaming state, Cmd+J), `review.tsx` (how a proposal diff is shown and approved through `proposal.decide` or its equivalent), `fake.ts` (how recordings match), and the AI-4 test that walks every feature's instructions.

Tommy's words: "i should be able to hit a keystroke and just add info about the world which is internalized properly." Internalized means the fact lands on the right entry with the right links and year, not in a notes pile.

Deliverables:

1. **The box.** Cmd+K from any screen (and the status bar Add button) opens a dialog over the screen: a heading "Add to the bible", the story time in words, one multi-line text field (auto-grown, focused), hint "Enter files it, Shift+Enter for a new line", Escape closes. Focus trap as the Story Time dialog does (`focusTrap.ts`). Reopening shows the last unsent text.
2. **The run.** Enter starts a `capture` run through the Claude runtime with the text as material (AI-5) and the story time, the chapter being written and the AI-2 tools. The system prompt tells Claude: look up every name in the text with the tools; file each fact on the entry it belongs to (a character's `placesLived`, `voiceNotes`, `backstory`, a new or existing world event with its year, a place, a cultural entry, a glossary term, a fact linked to the characters it concerns, a relationship); use the story year when the text gives none; set `status` to `idea` unless the text says it is established; set provenance to say it came from a capture on that date; make one `propose_change` per entry; then answer in one short line saying what was proposed; the prose prohibition (`PROSE_REFUSAL_RULE`). As proposals arrive they show in the box as cards with the ED-7 diff (reuse the review queue's diff rendering), each with a checkbox ticked by default; the streaming text and a Stop button show as in the panel.
3. **File it.** "File it" (Cmd+Enter) approves every ticked proposal through the existing `applyProposal` path and rejects the unticked ones, in order, and records one undo step for the whole filing (the undo helpers in `undo.tsx`; if an approval cannot be undone through the existing command types, add the smallest command that can). Then the box shows "Filed" with one link per entry (opening it through `claudeNav.openEntry`) and a "Add another" control. "Review later" closes the box with the proposals pending in the queue (they already are). Escape does the same. Nothing is written before File it (AI-3).
4. **KB-7 offline.** When the runtime reports no key, offline, or a failed run, the box saves the text as an open question (title: the first line, body: the text, tags `capture`, the story time in the body) through the write path, says "Saved as an open question" with a link, and keeps the text until that succeeds.
5. **Recordings.** Add recordings to `fixtures/claude/recordings.json` for the fixture bible: one capture that files a place lived on a character and a new world event (two `propose_change` steps and a one-line answer), one that proposes a fact linked to two characters. Match on the capture text.
6. **Tests.** Unit: the capture instructions contain the prose prohibition and the filing rules (extend the AI-4 walk; it should pick the feature up from `FEATURES` automatically). Integration: a recorded capture run queues the expected proposals with `source: 'claude'`, status `idea`, provenance naming the capture, and the story year; filing approves the ticked ones and rejects the rest; the offline path writes the open question. E2e `tests/e2e/capture.spec.ts`: KB-6 Cmd+K opens the box from the dashboard and from the tree; typing the recorded text and Enter shows two proposal cards with diffs; untick one, Cmd+Enter files the other and the entry shows the change and the "Filed" links open it; Cmd+Z undoes the filing; Review later leaves a pending proposal in the review queue; KB-7 with the key removed Enter saves an open question. NF-2: every control in the box takes focus, Escape closes.
