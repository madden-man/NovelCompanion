# A47 editable brief: the one editing primitive (IP-1)

Read `docs/briefs/A47-common.md` first. You own `src/renderer/src/workspace/editable/` (new), the Characters proof in `character.tsx` and `views.tsx`, and the tests named in the common brief. Branch `a47-editable`, worktree `.claude/worktrees/a47-editable`.

What exists and why it is not enough: `fields.tsx` (`Field`) is the generic form field used by `EntryPane`; it is a form, not text. `editor.tsx` (`useAutosave`) autosaves a whole entry draft and records one `editCommand` per save; `sessions/common.tsx` (`updateWithUndo`) writes one patch and records the step. The tree inspector (`tree/TreeView.tsx` 1115 to 1222), the moments table (`backstory/MomentsTable.tsx` 155 to 208), the outline bar title (`outline/Scenes.tsx` 1337 to 1346) and the cultural lines (`culture.tsx` 597 to 652) each hand-roll "click, type, Enter or blur saves, Escape reverts" with their own undo step. `richText/RichText.tsx` is the A44 box (`registerTextTarget` ties it into Cmd+Z). `undo.tsx` holds `useUndo`, `markSaved` and the `data-field` rule that lets Cmd+Z undo unsaved typing before the app history. The audit's demo tile (section 2 of the artifact, summarised in `docs/EDIT-AUDIT-2026-10-22.md`) is the behaviour to match.

Deliverables:

1. **`Editable`** in `workspace/editable/Editable.tsx`: one component that draws a value as text (or a placeholder in the primary text colour, never grey) and becomes a field on click, Enter or Space. Kinds: `text`, `year`, `number`, `rich`, `select`, `chips`, `date`. Props, at least: `kind`, `value`, `label` (the accessible name and the undo step's noun), `onSave(next)` returning a promise, `placeholder`, `options` and `onAddNew(label)` for `select` and `chips`, `disabled` with `reason` (ARCH-6 read-only: the text shows, the field never opens, the reason is the title), `inline` or `block` layout, `testId`, `data-field` pass-through. Enter or blur saves, Escape reverts, Shift+Enter is a newline in `rich`. The field takes the text's place and size (same font, same box; measure the text's width for inline fields so nothing jumps), scrolls nothing and opens no dialog. A saved tick shows for about a second (`data-save-state` of `saving`, `saved`, `error`), and an error keeps the field open with the message under it in plain words. `select` and `chips` show "Add new..." as the last option; picking it turns into a text field for the new item's label, calls `onAddNew`, then saves the new value, as one step from the writer's side (two commands are fine if the second cannot be recorded; say which in the report). `chips` adds through a picker (reuse the app's reference picker from `fields.tsx` if it stands alone, else a small combobox) and removes with a button on the chip; each add or remove saves at once. `date` reuses the one-box date parser from `src/shared/domain/dates.ts` and its "could not read" explanation. `year` and `number` accept digits only and reject empty unless `allowEmpty`.
2. **Helpers** so screens write one line: `EntryEditable` (`collection`, `id`, `path`, `kind`, the rest as above) that reads the entry, writes the patch through `entry.update`, records `editCommand` with the field's label from the manifest, calls `undo.markSaved`, and shows the ED-10 issue when the schema rejects the value; `useEditableSave` (or similar) for values that are not entry fields, taking a `run` op builder so the caller records the step. Reuse `updateWithUndo` from `sessions/common.tsx` or move it into `editable/` and re-export from where it was.
3. **Undo**: every save is exactly one step; Cmd+Z inside an open field with unsaved typing undoes the typing (the existing `data-field` rule), Cmd+Z after a save undoes the save. Prove it in `tests/e2e/editable.spec.ts` on the Characters page.
4. **The Characters proof**: on `character.tsx` the full name and Chinese name are `Editable` text in the heading (the Edit name button and Done go), birth and death are `Editable` date, status is `Editable` select, families stay chips but through `Editable chips`; the three text boxes stay the A44 boxes (they already behave). In `views.tsx` a character list row renames in place (double-click or F2 on the row, Enter saves) and New character takes a name. Keep the tests in `tree.spec.ts` and `editing.spec.ts` that cover the page passing, changing only the lines the new controls need.
5. **Style**: `editable.css` next to the component, tokens only, both themes, a dashed underline on hover for inline text, a dashed box on hover for block kinds, nothing grey. Check at 1200x800 and 390 wide.
6. **Tests**: `tests/unit/editable.test.ts` (pure parts: the width measure can be skipped, the value parsing per kind, the Add new flow's state), `tests/e2e/editable.spec.ts` with at least: "IP-1 a text field opens on click, saves on Enter, reverts on Escape, and the page does not move" (compare the bounding boxes of the next sibling before, during and after), "IP-1 a year field saves on blur as one undo step and Cmd+Z puts the old year back", "IP-1 a select with Add new creates the list item and picks it", "IP-1 a chip row adds from the picker and removes with its button, one step each", "IP-1 a date field explains what it could not read and keeps the old value", "IP-1 ARCH-6 a read-only field shows the reason and never opens", "IP-1 NF-2 every kind works from the keyboard and labels use the primary text colour in both themes".

Report the component's API in full (every prop, every kind's value type, the helpers' signatures, one example per kind), since every wave 1 builder codes against it from your report.
