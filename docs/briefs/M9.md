# M9 brief: Google Drive

**Superseded (2026-10-11).** This brief was written before the build and no longer describes the code. Read `docs/ARCHITECTURE.md` ("Google Drive") and `docs/DRIVE-SETUP.md` instead. What differs:

- Keychain: service `novel-companion-google` with account `oauth-client` (client ID and secret) and account `oauth-tokens`. The brief's `novel-companion-google-oauth` and `novel-companion-google-tokens` are not used.
- There is no `googleapis` package; Drive v3 and the OAuth endpoints are called with Node's `fetch` (`src/main/drive/api.ts`, `oauth.ts`).
- There is no `driveLinks` collection; links and versions seen live in the bible's `meta` document `drive`.
- There is no `client.ts`, `real.ts`, or `mock.ts`. The code is `api.ts`, `oauth.ts`, `secrets.ts`, `service.ts`, and `index.ts`; the fake Google for tests is `tests/helpers/fakeGoogle.ts`.

Criteria: GD-1 to GD-5. Read first: `docs/ARCHITECTURE.md`, `SPEC.md` sections 5.17, 8 (T-2 Drive import and export against a mocked Drive), and the mockup `mockups/claude-import.html` (Drive card, linked files with changed flags, export file tree, disconnect). Then the code from M0 to M8, especially the M5 import engine and the M7 manuscript import entry point. Check current Google documentation for the Drive API v3 scopes and the desktop (loopback) OAuth flow before coding; cite the URLs in your report.

The OAuth client ID and secret will be in the macOS keychain under service `novel-companion-google-oauth`, account `novel-companion`, as JSON `{ "client_id", "client_secret" }`. It may not exist yet when you build; the app must work fully without it (GD-5) and show the exact manual steps when it is missing. Never print it. Tests never use it; they use the mock.

Deliverables, keeping `npm test` green:

1. **Drive client interface** `src/main/drive/client.ts` with `real.ts` (googleapis, loopback OAuth on a random localhost port, tokens stored in the keychain service `novel-companion-google-tokens`, refresh handled, scopes `https://www.googleapis.com/auth/drive.readonly` for import and `https://www.googleapis.com/auth/drive.file` for export, requested as the narrowest set that works, verified against the docs) and `mock.ts` (an in-memory Drive seeded from `tests/fixtures/drive/` with files, folders, modified times, and export of Docs to `.docx` and Sheets to `.xlsx` returning the fixture files) (GD-1).

2. **Linking files** (GD-2): a picker that lists folders and files from Drive (Word, Excel, Google Docs, Google Sheets) and stores links in a `driveLinks` collection with file ID, name, mime type, last imported modified time and content hash; linked files feed the M5 import mappings and the M7 manuscript import (a Google Doc exports as `.docx`, a Sheet as `.xlsx`).

3. **Change detection** (GD-3): on launch and on demand, compare each linked file's modified time and hash with the stored values and report which changed; "Review" opens the M5 re-import change set, which is never applied without approval.

4. **Export** (GD-4): writes the whole bible to a chosen Drive folder as Markdown, one file per entry organized in folders by section, plus one `bible.json` (the M5 export format), creating or updating files the app created (drive.file scope) and never touching others; a preview tree before writing; progress and a final count.

5. **Disconnect** (GD-5): removes tokens from the keychain and clears link metadata that depends on the account; everything else keeps working; tests assert the app has no Drive dependency on launch.

6. **Tests**: integration against the mock: link files, detect a changed file after the mock's modified time changes, import a linked Doc as a chapter, export and read back the written tree, disconnect clears tokens (keychain mocked); e2e: with the mock injected through an environment flag accepted only when not packaged (same pattern as the test database URI), connect, link, see a changed flag, export. The manual steps text in the app must match `docs/DRIVE-SETUP.md`, which you write: project, enable Drive API, consent screen external in testing with the user as test user, Desktop OAuth client, the `security add-generic-password` command.
