# A47 model brief: the vocabulary belongs to the writer, stored side (IP-8 to IP-12, IP-14)

Read `docs/briefs/A47-common.md` first. You own the schema, the lists, the bible settings, migration 11 and the handlers the common brief lists. Branch `a47-model`, worktree `.claude/worktrees/a47-model`. The screens that use what you build come in wave 1 (`a47-vocab`, `a47-grids`, `a47-house`); you build the stored side, the channels, and the fewest renderer lines that keep the app compiling and its tests green.

Where things are today: `src/shared/schema/lists.ts` (`ListItem`, `ListDoc`, `LIST_IDS`, `CONFIG_LIST_IDS`, `FIXED_ITEM_LISTS`), `manifest.ts` 148 to 157 (`STATUS_OPTIONS`, `PROVENANCE_OPTIONS` as enums on `commonFields`), `world.ts` 53 to 63 (the six age groups) and `culture.ts` 39 to 48 (the decade), `worldGrid.ts` 11 to 12 (2025 to 2100) and 520 to 521 (3 back, 1 ahead), `backstoryGrid.ts` 389 (reach 1), `family.ts` 21 to 25 (`FAMILY_COLORS`, four tokens), `migrations/003-era-defaults.ts` 11 to 24 (the era defaults constant), `ipc.ts` 734 to 759 (`lists.get`, `lists.rename`, `lists.addItem`, `lists.removeItem`), the bible settings in `meta` (find the brief window and budget, the romanization setting, `communityNotes`; `repository.ts` from line 1687), `briefs.ts` 66 and `src/shared/domain/brief/*` (the section headings and the SB-5 status rule), the literals "New chapter", "New section", "Book 1", "Part 1", "present", "backstory", "New era" wherever they are created.

Deliverables:

1. **IP-8 lists.** `ListItem` gains `color` (nullable string, a CSS hex) and `extra` (a record of string or number values, default empty) so one shape serves every list. New channels `lists.move` (listId, itemId, index) and `lists.setParent` (listId, itemId, parentId or null) through the repository, with undo `run` ops exported from `src/shared/undoCommands.ts` next to the existing list commands. A new list `regions`: migration 11 seeds it from every distinct region string on world events (trashed ones too), rewrites `worldEvents.regions` to item IDs, and the schema, manifest (`f.refs`-like list refs), importer mapping, search tokens and the timeline's region chips follow. `lists.rename` on `regions` renames it everywhere because events store IDs. Renaming keeps `FIXED_ITEM_LISTS` only if some list still needs it; `statuses` and `provenance` leave it.
2. **IP-9 statuses and provenance.** The two lists hold the real items: migration 11 writes `canon`, `planned`, `idea` and `researched`, `invented` with labels, colours (pick tokens that pass contrast in both themes; the hex values go in `extra` or `color`, the renderer maps them) and `extra.kind` for statuses. `commonFields` `status` and `provenance` become list references (the kind `Union.type` uses), the write path refuses an ID not in the list with a plain error ("Status x is not in the statuses list"), and `lists.removeItem` refuses an item in use as it does today. The SB-5 rule and everything that compares `status === 'canon'` reads the item's `extra.kind` through one helper in `src/shared/domain/lists.ts` (`statusKind(lists, id)`); the brief, the continuity checks and the selection tests keep their answers on the fixture.
3. **IP-10 age groups and the time unit.** A list `ageGroups` seeded with the six bands (`all` and the five ranges; `extra.from`, `extra.to` in years, `to` absent for the open band); `culturalEntries.demographic` becomes a list reference with the same IDs so no data moves. The bible settings gain `cultureUnit` (`decade`, `five`, `one`); `culture.ts` takes the unit as a parameter wherever it used the decade, with unit tests for each unit.
4. **IP-11 numbers.** The bible settings gain `numbers`: `timelineStart` (2025), `timelineEnd` (2100), `windowBefore` (3), `windowAfter` (1), `pickerReach` (1), `autosaveMs` (500), with `autosaveMaxMs` fixed at the larger of 700 and `autosaveMs` + 200. One channel pair (`settings.get`, `settings.set` with a partial, or whatever the existing bible-settings channel is called; extend rather than add if one exists) and an undo command per field in `undoCommands.ts`. `worldGrid.ts`, `backstoryGrid.ts` and the brief window take them as parameters (pure functions with defaults so the existing tests still pass unchanged where the defaults match); the renderer call sites pass the stored numbers with the fewest lines.
5. **IP-12 family colour and era defaults.** `families.color` becomes any CSS hex (`z.string().regex(/^#[0-9a-f]{6}$/i)`), migration 11 maps the four tokens to hex values that match the current tokens in `theme.css` (read them, do not guess; keep a light and dark pair if the token differs by theme, in which case store the light value and let the renderer keep the token mapping for the four known values). `eraDefaults` gets `eraDefaults.get` and `eraDefaults.set` (name, startYear, endYear per row) and New bible copies the stored rows; migration 3's constant becomes the seed only.
6. **IP-14 templates.** The bible settings gain `templates`: `chapterTitle` ("New chapter"), `sectionTitle` ("New section"), `partTitle` ("Part {n}"), `bookTitle` ("Book {n}"), `strandPresent` ("present"), `strandBackstory` ("backstory"), `eraName` ("New era"), `briefHeadings` (the brief's section headings in order, from `briefs.ts` and the brief domain), `linkTypeLabels` (the tree legend's labels). Every create path and the brief read them through one helper (`templates(settings)` with the defaults filled in); the importer keeps its own names.
7. **Migration 11** with a snapshot first, idempotent, a `meta.migration11` summary (counts of regions made, events rewritten, families recoloured), `tests/integration/migration11.test.ts` on the fixture and on a copy at version 10. Bump the schema version once; `session.ts` already refuses a newer bible.
8. **Fixture and tests.** `fixtures/novel/lists.json` gets the seeded items so the fixture loads at version 11 without migrating; `fixtures/expected/*` where a region or status is asserted. Unit tests for every pure helper (`statusKind`, the unit-aware culture functions, the parameterised grids, `templates`), integration tests for every channel including the refusals and the undo of a move, a re-parent, a settings number and an era default (`tests/integration/undo.test.ts` has the pattern).

Report the stored shapes and every channel with its request and response, and the names of the helpers, so `a47-vocab`, `a47-grids` and `a47-house` can code against them.
