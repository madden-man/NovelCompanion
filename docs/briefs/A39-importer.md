The 2026-10-11 sections of `EASTWINDS-DATA.md` say what the real bible already holds and why; the re-import must update those entries, never duplicate them (IM-3).

Deliverables:

1. **Mappings to the new model** (`defaultMappings` in `eastwinds.ts`, the plan in `run.ts`, the pure mapping in `src/shared/domain/import/`): the High Level sheet's chapter rows become chapters per A29 (48 in Book One, 12 per part, a present strand primary and a "Backstory: ..." strand for the other span, the Introduction in 2078; matching existing chapters by part and title so a re-import updates them); the High Level sheet's category rows (the world tracker: a grid, row label by year column, with heading rows for the groups) become world events with `categoryId` from the `eventCategories` list (group and subcategory, adding missing ones to the list as before) and `regions` where the sheet says; the Sullivan and 李 sheets become moments (one per row: the character from the sheet's name column or the sheet, `year`, `title`, `body` from "how they experience it", `worldContext` from "relevant world events"), matched on character and sheet and title the way beats were (a changed year updates the moment); Plot v1 rows are neither chapters nor beats for Book One (A29) and stay chapters for Book Two until the High Level sheet plans it; the Life documents (IM-4) still come in as character backstory. No mapping writes a dropped kind. `importProposals` (IM-5) proposes characters, world events, moments and open questions only.
2. **IM-2 and IM-7 stay true**: rows that fail are reported with the reason; a value that differs between two sources keeps the most recently modified source and files an open question; every imported entry records its source file and location (IM-6).
3. **The script.** `npm run import:eastwinds` (dry run by default, `--yes` to apply, a snapshot first) runs against the new mappings; the report counts chapters, world events, moments and characters touched. Rehearse only on a local test copy: open the cluster for nothing. The architect runs the real re-import with Tommy.
4. **Tests.** Unit: each mapping as a pure function over small parsed sheets shaped like the real ones (a High Level chapter row to a chapter with two strands; a category grid cell to a world event with its category and year; a Sullivan row to a moment; a 李 row with a Chinese name resolving to the character; a Plot v1 Book One row producing nothing and a Book Two row a chapter). Integration (`eastwinds.test.ts`, `import.test.ts`): a full run on the fixture workbook under `fixtures/files` (extend it if it lacks a grid sheet or a moments sheet) into a fresh bible, then the same run again changes nothing (IM-3), then a changed year updates the moment in place, and the failing-row report (IM-2). E2e (`import.spec.ts`): the mapping screen shows sheet to section and column to field for the new sections, the preview lists moments and world events, and an import creates them.
